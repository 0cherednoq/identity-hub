# Наблюдение выводит аккаунт из `deleted`

**Библиотека:** `identity_hub==1.0.0a2`. Пути — от `site-packages/identity_hub/`. Найдено чтением кода и тестами server-admins (хаб на `MemoryStore` и на PostgreSQL).

**Тип:** ошибка. **Важность:** высокая.

Состояния `deleted` нет ни в `sticky`, ни в `confirm_leaving` (`domain/region_specs.py`,
стр. 63–65), а `_apply_observation` таблицу переходов не проверяет. Любое наблюдение (например,
`limited`) сразу «воскрешает» удалённый аккаунт. Воспроизведено тестом на хабе в памяти:
`deleted` → `observe(limited)` → состояние `limited`.

**Обход в server-admins:** репортёр сигналов сам пропускает сигналы репутации для аккаунта в
`deleted`. Внутри операции (`Fault`) такой защиты нет: классификатор состояния не видит.

**Предложение:** сделать `deleted` терминальным для наблюдений (выход только явной
административной командой) или хотя бы требовать подтверждения, как у `frozen`.
