# Ограничения альфа-версии 1.0.0a3

Известные пробелы и неочевидное поведение. API может измениться в следующих альфа-версиях.

## Пробелы API

| Что | Как обойти сейчас |
|---|---|
| Библиотека не запускает общую сверку, обычный вход и перепроверку прокси сама | Периодически вызывайте `sync.refresh_many()`, `auth.login_many()`, `proxies.recheck_due()`; импорт с `AcceptPolicy` проверяет отдельный acceptance-worker |
| Проба (`sync.refresh`/`sync.refresh_many`) не работает для аккаунтов в `provisioning`: бросает `OperationNotAllowed(lifecycle)` | Логиньте через `auth.login` (он работает), проверку делайте после перевода в `ready` |
| Обновление сессии без входа (`SessionRefresher.refresh`) библиотека не вызывает | Обновляйте сессию своим кодом через `lease.save_session` |
| `idempotency_key` и `pools.revoke` не работают для shared-аренд (ключ даёт `ValidationFailed`) | Для задач, требующих этого, используйте эксклюзивный сервис |
| Нет своих типов событий | Используйте свою шину для событий приложения |
| Нет синхронного API | Только `asyncio` |
| `error_score` не сбрасывается при снятии карантина | Снижается сам успешными операциями (×0.5) |

## Поведение, которое легко упустить

- **`secret_storage="plaintext"` раскрывает credentials и сессии любому, кто читает их таблицы
  или дамп базы.** Хаб предупреждает об этом при старте и в `identity-hub doctor`; ограничьте
  права PostgreSQL и верните шифрование командой `identity-hub secrets convert --to encrypted`.
- **Квоты при выборе аккаунта учитываются только с `require_quota=True`.** Без флага
  `pool.lease(for_operation=...)` может выдать аккаунт с исчерпанной квотой. С флагом выборка
  переносит исчерпанные аккаунты в хвост отдельного порядка LRU: см.
  [квоты при выборе аккаунта](08-limits.md).
- **Повтор `key` операции не пропускает тело блока** — проверяйте `op.duplicate`. После
  неуспешной попытки повтор — новая попытка (`duplicate=False`), см.
  [идемпотентность операции](08-limits.md#идемпотентность-операции).
- **Ключ операции действует в пределах пространства** и не привязан к аккаунту: включайте в
  него id задачи. Тот же ключ с другим видом операции — `IdempotencyConflict`.
- **`identities.ensure` не обновляет существующий аккаунт**, а `create`/`ensure` по умолчанию создают его в `provisioning`.
- **Аренда из `pool.acquire()` не запускает heartbeat автоматически.** Вызывайте
  `await lease.renew()` чаще, чем `ttl − safety_margin`, либо используйте `async with pool.lease()`.
- **Новый подписчик событий** по умолчанию получает всю хранимую историю журнала; `subscribe(..., start="now")` начинает с текущего момента.
- **Ёмкость прокси** (`max_identities`) считается только для sticky-привязок; при `sticky=False`
  один прокси может обслуживать любое число аренд.
- **Форматы с потерями предупреждают, но по умолчанию продолжают конвертацию.** Для импорта,
  где потеря недопустима, передавайте `strict=True`. Partitioned cookie нельзя незаметно
  превращать в обычную; Selenium, Netscape и HTTP jar их пропускают с предупреждением.
- **Автоопределение формата намеренно ограничено.** Pickle может выполнить код, а Chrome
  `Cookies` SQLite содержит платформенно зашифрованные значения, поэтому оба формата всегда
  отклоняются. Экспортируйте JSON или Netscape/cookies.txt.
- **Acceptance-worker не решает challenge за человека.** При `skip_on_challenge=True` (по
  умолчанию) durable-отметка снимается, а аккаунт остаётся в `provisioning`; ответьте через
  `auth.answer_challenge` и активируйте его приложением. При `False` отметка остаётся в очереди,
  но новые попытки входа не выполняются, пока challenge открыт.
- **`verify_sessions=False` вместе с `AcceptPolicy` доверяет импортированной сессии.** Такой
  аккаунт уже `authenticated`, поэтому worker считает его успешно проверенным; используйте это
  только для доверенного источника. По умолчанию при политике включается проверка сессии.
- **`MERGE` не хранит несколько кандидатов сессии в одном слоте.** Разные кандидаты задавайте
  разными слотами. При конфликте с активной сессией режим `keep` оставляет текущую; `replace`
  отзывает её и пишет новую ревизию. Состояния `lifecycle`, `standing` и `auth` импорт не меняет.
- **Дубликат отклонённой или `revoked` пары не считается новой.** `MERGE` не снимает отметку
  отказа и не воскрешает запись; исправленное значение передайте как новую пару либо замените
  запись явной командой.

## Известные дефекты

- **Фоновый импорт с нерасшифрованными записями** (`imports.stage`, мастер-ключ убран до
  ротации) завершается `failed`; сами записи остаются в `ih_import_items` до срока
  `Retention.import_runs` и переоборачиваются `rotate-key`, когда ключ вернут. Команды повторной
  обработки такого прогона пока нет — после возврата ключа загрузите файл заново.
- **Производительность админ-чтения на объёме** (`R2-D08`, `R2-D09`): поиск аккаунтов для
  админки делает запросы на каждую строку, а список по умолчанию не попадает в индекс. На сотнях
  тысяч аккаунтов страница медленнее бюджета p95; исправление — `I6.2`.
