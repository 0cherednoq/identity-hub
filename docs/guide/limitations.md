# Ограничения альфа-версии 1.0.0a1

Известные пробелы и неочевидное поведение. API может измениться в следующих альфа-версиях.

## Пробелы API

| Что | Как обойти сейчас |
|---|---|
| Нет команды `ban()` / `freeze()` | `space.override(id, Override("standing", "", "banned", reason=..., actor=...))` |
| Нет публичного метода «сообщить наблюдение» (например, из вебхука платформы) | Классификатор ошибок в операциях, пробы + `resync`, либо override |
| Библиотека не запускает сверку, вход и перепроверку прокси сама | Периодически вызывайте `reconcile()`, `run_logins()`, `recheck_proxies()` |
| Проба (`resync`/`reconcile`) не работает для аккаунтов в `provisioning`: бросает `OperationNotAllowed(lifecycle)` | Логиньте через `run_login` (он работает), проверку делайте после перевода в `ready` |
| `Authenticator.refresh()` не вызывается | Обновляйте сессию своим кодом через `lease.save_session` |
| Нет продления/`renew` для аренды из `pool.acquire()` | Для длинной работы используйте `async with pool.lease()` |
| Нет массовых изменений аккаунтов | Цикл по отдельным методам |
| Нет своих типов событий | Используйте свою шину для событий приложения |
| Нет синхронного API | Только `asyncio` |
| `error_score` не сбрасывается при снятии карантина | Снижается сам успешными операциями (×0.5) |
| Регион `auth` застревает в `logging_in`, если процесс упал во время входа | Override `auth`/`default` → `no_session` |

## Поведение, которое легко упустить

- **Квоты не учитываются при выборе аккаунта.** `pool.lease(for_operation=...)` может выдать
  аккаунт с исчерпанной квотой; `QuotaExhausted` бросает `lease.operation()`.
- **Повтор `key` операции не пропускает тело блока** — проверяйте `op.duplicate`.
- **Ключ операции уникален во всей базе**, не только в рамках аккаунта — добавляйте префикс.
- **`register` не обновляет существующий аккаунт** и по умолчанию создаёт его в `provisioning`.
- **Аренда из `pool.acquire()` без heartbeat** считается потерянной через ~40 с (ttl − safety_margin).
- **Новый подписчик событий** получает всю хранимую историю журнала.
- **Override региона `auth`** — передавайте `key="default"`, иначе поле `auth_state` аккаунта не обновится.
- **Ёмкость прокси** (`max_identities`) считается только для sticky-привязок; при `sticky=False`
  один прокси может обслуживать любое число аренд.

## Известные дефекты

- **`LeaseMode.SHARED` некорректен для параллельных аренд.** Каждый захват увеличивает
  fencing, поэтому у более ранней из параллельных аренд `operation()` и `save_session()`
  падают с `StaleFencing`; все захваты выдают один и тот же аккаунт; `idempotency_key` не
  работает. Используйте эксклюзивный режим.
- **`identity-hub rollups --purge-minutes`** ничего не делает (недостижимый код в CLI).
- **Незавершённые фоновые импорты** (`stage_import`) не перешифровываются при ротации ключа —
  не удаляйте старый ключ, пока они не обработаны.
