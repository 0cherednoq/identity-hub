# Импорт аккаунтов

Страница `/spaces/{space_slug}/imports` принимает UTF-8 CSV, JSONL или NDJSON и запускает долговечный импорт в выбранное пространство. Роль `viewer` может читать историю и отчёты; запуск и отмена доступны `operator` и `admin`.

## Подготовка файла

JSONL содержит один JSON-объект на непустую строку. Обязательное поле — `external_ref`.

```json
{"external_ref":"account-001","profile":{"display_name":"First","country":"UA"},"tags":["migration"]}
{"external_ref":"account-002","labels":{"team":"ops"}}
```

CSV требует заголовок `external_ref`. Структурные поля передаются как JSON; `tags` можно передать JSON-массивом или списком через `;`.

```csv
external_ref,profile,tags
account-001,"{""display_name"":""First"",""country"":""UA""}",migration;priority
```

Допустимые поля: `external_ref`, `id`, `attributes`, `profile`, `labels`, `tags`, `note`, `credentials`, `sessions`, `links`, `proxy`, `verifications`. Неизвестные CSV-колонки и поля JSON отклоняются. Ссылки задаются как роль → `service:external_ref`; для того же сервиса префикс можно опустить.

Ограничения запроса:

- файл — не более 10 МиБ;
- записей — не более 10 000;
- время серверного разбора — не более 5 секунд;
- не более 100 элементов в основных mapping/list-полях и глубина вложенности не более 6;
- `external_ref` должен быть уникален внутри файла.

## Запуск и наблюдение

1. Выберите файл и сервис.
2. Выберите поведение для существующего аккаунта: `skip`, `update_session` или `fail`.
3. При необходимости включите проверку сессий и задайте метки партии как `key=value`.
4. Укажите причину и запустите импорт.

UI опрашивает активный run каждые две секунды. Итог показывает созданные аккаунты со ссылками, пропущенные строки и ошибки с номером строки. Credentials и session payload в отчёт не попадают.

Кнопка отмены выставляет запрос на остановку. Уже claimed-пакет завершается атомарно; новые пакеты после этого не начинаются.

## Восстановление после сбоя

Исходный файл не сохраняется. После валидации каждая нормализованная запись временно хранится в `ih_import_items` в envelope-encrypted виде. Worker использует lease-like claim и fencing token. После рестарта истёкший claim забирается повторно; заранее назначенный identity UUID предотвращает повторное создание, даже если процесс остановился между commit аккаунта и commit прогресса.

После `succeeded`, `failed` или `cancelled` staging удаляется. Redacted run хранится 90 дней. Если run долго остаётся `running`, проверьте dispatcher на странице фоновых работ и readiness приложения; вручную менять строки staging не следует.
