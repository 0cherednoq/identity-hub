# Реализация Identity Hub Admin

Этот каталог содержит полный набор документов для автономной реализации веб-приложения
Identity Hub Admin: Python-бэкенд, React-фронтенд, необходимые расширения библиотеки,
тестирование, упаковку и выпуск.

## С чего начать

1. Прочитайте [`AUTONOMY.md`](AUTONOMY.md). Это протокол запуска, продолжения и завершения
   автономной сессии.
2. Откройте [`PROGRESS.md`](PROGRESS.md). Если задача уже `in_progress`, продолжите её с первого
   незакрытого шага. Иначе выполните `python docs/admin/progress_tool.py next`.
3. Прочитайте раздел выбранной задачи в [`PLAN.md`](PLAN.md) и применимые решения из
   [`DECISIONS.md`](DECISIONS.md).
4. Для продуктового контекста используйте существующие документы:
   - [`ADMIN-PAGES.md`](ADMIN-PAGES.md) описывает страницы, данные и действия;
   - [`ADMIN-STACK.md`](ADMIN-STACK.md) фиксирует стек, сборку и способы запуска;
   - [`FRONTEND-DESIGN-SYSTEM.md`](FRONTEND-DESIGN-SYSTEM.md) задаёт UI-архитектуру и визуальные
     ограничения.
   - [`IMPORTS.md`](IMPORTS.md) описывает формат, лимиты, запуск, отмену и восстановление импорта.
   - [`ROLLUPS.md`](ROLLUPS.md) фиксирует временные корзины, метрики, rebuild и retention аналитики.
   - [`SNAPSHOTS.md`](SNAPSHOTS.md) описывает почасовые срезы, coverage и безопасный backfill.
   - [`ANALYTICS.md`](ANALYTICS.md) фиксирует каталог метрик, формулы, API, URL-state и экспорт.

## Граница с планом библиотеки

План библиотеки ведётся отдельно в [`docs/plan`](../plan/). Админка не дублирует задачи `P*`.
Если задача `A*` требует изменить публичный контракт, схему или поведение `identity_hub`, исполнитель
сначала регистрирует отклонение в `docs/plan/DECISIONS.md`, затем меняет библиотеку и запускает оба
набора проверок. Текущий статус библиотечных задач всегда берётся из
[`docs/plan/PROGRESS.md`](../plan/PROGRESS.md), а не копируется сюда.
