# Решения по Identity Hub Admin

Этот журнал снимает неоднозначности, на которых автономный исполнитель иначе остановился бы.
Решения со статусом `по умолчанию` можно пересмотреть отдельной новой записью. Старые записи не
переписываются: заменённое решение помечается ссылкой на новое.

## Принятые решения

| ID | Тема | Решение | Статус |
|---|---|---|---|
| A-D001 | Размещение кода | Админка живёт в `admin/` этого репозитория, но собирается как отдельный Python-дистрибутив `identity-hub-admin`. Это сохраняет атомарные изменения библиотеки и админки. Позже каталог можно вынести без смены импортов. | по умолчанию |
| A-D002 | Технологии | Бэкенд: Python 3.12+, Litestar 2, Pydantic 2. Фронтенд: Node 22 LTS, npm, React, TypeScript strict, Vite, Tailwind CSS 4, shadcn/ui, TanStack Query/Table/Router, React Hook Form, Zod, Recharts. | принято из `ADMIN-STACK.md` |
| A-D003 | Граница данных | Бэкенд админки не выполняет SQL к таблицам Identity Hub. Чтение идёт через публичные read-модели библиотеки, запись только через её команды. Новая выборка сначала появляется как типизированный контракт библиотеки. | принято |
| A-D004 | Версия API | Все прикладные маршруты имеют префикс `/api/v1`. Несовместимое изменение создаёт `/api/v2`; добавление полей остаётся совместимым. OpenAPI является источником TypeScript-клиента. | по умолчанию |
| A-D005 | Размещение пространства | `space_slug` входит в URL API и UI, но доступ проверяется по `AdminPrincipal.allowed_spaces`. Значение из URL никогда не считается авторизацией. | принято |
| A-D006 | Роли | В v1 три роли: `viewer` читает несекретные данные, `operator` выполняет обычные действия, `admin` управляет каналами, endpoint-ами, импортом, доступами и показом секретов. Каждое действие дополнительно проверяет пространство. | по умолчанию |
| A-D007 | Вход | Standalone-режим поддерживает bearer-токены из конфигурации и сессию после входа по паролю. Встроенный режим может доверять заголовкам только от явно настроенного reverse proxy. OIDC реализуется на proxy-уровне, не внутри пакета v1. | по умолчанию |
| A-D008 | Веб-безопасность | Сессионная аутентификация использует `HttpOnly`, `Secure`, `SameSite=Lax` cookie и CSRF double-submit для изменяющих запросов. Bearer-запросы не используют cookie и CSRF. CORS по умолчанию выключен. | принято |
| A-D009 | Аудит действий | Каждая мутация принимает `reason`, `expected_revision` где применимо, `Idempotency-Key` и `AdminPrincipal.actor`. Успех и отказ, затронувшие доменное состояние, оставляют событие или аудит библиотеки без секретов. | принято |
| A-D010 | Ошибки API | Один envelope: `error.code`, `error.message`, `error.details`, `error.request_id`. Доменные конфликты возвращают `409`, ошибки ревизии `412`, валидация `422`, запрет `403`, отсутствие `404`, лимит `429`. Стек и секретные значения клиенту не возвращаются. | по умолчанию |
| A-D011 | Пагинация | Большие списки используют непрозрачный keyset-cursor и стабильную сортировку. Offset применяется только к маленьким справочникам. Фильтры и курсор находятся в URL интерфейса. | принято |
| A-D012 | Обновление данных | В v1 нет WebSocket. TanStack Query опрашивает оперативные страницы каждые 15 секунд, фоновые работы каждые 10 секунд, спокойные справочники каждые 60 секунд. Вкладка вне фокуса не опрашивается. | по умолчанию |
| A-D013 | Локализация | Интерфейс v1 русский. Ключи сообщений отделены от компонентов, чтобы добавить локаль без переписывания страниц. API передаёт машинные коды и параметры, а не готовые русские ошибки. | по умолчанию |
| A-D014 | Время | Бэкенд хранит и отдаёт UTC ISO 8601. UI показывает время в таймзоне пространства, затем в настроенной таймзоне админки. Дневная аналитика считается в таймзоне пространства. | принято |
| A-D015 | Деньги и числа | Все счётчики и длительности передаются как числа, доли как значения `0..1`. UI форматирует их централизованно. На графиках отсутствующие интервалы заполняются нулём на бэкенде. | принято |
| A-D016 | Дизайн | UI следует `FRONTEND-DESIGN-SYSTEM.md`. Визуальные решения живут в токенах и shared-компонентах; страницы собираются из шаблонов и не задают собственные цвета, типографику, радиусы или тени. | принято |
| A-D017 | Секреты | Секреты отсутствуют в списках, кеше TanStack Query, логах, OpenAPI-примерах, аналитике и экспортируемых файлах. Показ выполняется отдельным не кешируемым запросом после повторного подтверждения и аудируется. | принято |
| A-D018 | Импорт | В v1 импорт принимает UTF-8 CSV или JSONL с лимитами размера и числа записей. Файл не сохраняется после разбора; хранится отчёт без исходных секретов. Большой импорт выполняется фоновой задачей с идемпотентным `run_id`. | по умолчанию |
| A-D019 | Фоновые задачи админки | Используются существующие `run_once(limit)` и dispatcher/maintenance библиотеки. Отдельная очередь Celery/RQ не вводится. Долгая операция хранит состояние в таблицах библиотеки и безопасно продолжается после рестарта. | принято |
| A-D020 | Аналитика | Оперативные счётчики считаются запросами, исторические графики читают `ih_stats_rollup`, а снимки распределений — `ih_state_snapshots`. Роллапы наполняются идемпотентным consumer-ом по курсору событий. | принято |
| A-D021 | Доступ к `/docs` и OpenAPI | В production схема доступна только `admin`; в development доступна всем локальным пользователям. Сгенерированный JSON фиксируется в репозитории и проверяется на drift в CI. | по умолчанию |
| A-D022 | Упаковка | Готовая статика входит в wheel. Node нужен разработчику и CI, но не пользователю wheel. Выпускаются wheel и multi-stage Docker image; запуск поддерживает standalone и Litestar plugin. | принято из `ADMIN-STACK.md` |
| A-D023 | Поддерживаемые браузеры | Последние две стабильные версии Chrome, Edge и Firefox. Safari проверяется best effort. Мобильный экран поддерживает просмотр и срочные действия, сложные таблицы допускают горизонтальную прокрутку. | по умолчанию |
| A-D024 | Доступность | Цель: WCAG 2.2 AA для основных потоков. Любое действие доступно с клавиатуры, фокус видим, статус не кодируется только цветом, диалоги удерживают и возвращают фокус. | принято |
| A-D025 | Коммиты | Одна задача `A*` завершается одним локальным коммитом `feat(Ax.y): ...` или `chore(Ax.y): ...`, включающим код, тесты и `PROGRESS.md`. Push и публикация без явного запроса запрещены. | принято |
| A-D100 | Контекст пространства | `space_slug` присутствует в URL для воспроизводимых deep links и cache keys. Источником авторизации остаётся `AdminPrincipal.allowed_spaces`; сессия не может неявно подменить slug запроса. | принято в A0.1 |
| A-D101 | Размер страницы аккаунтов | HTTP API админки использует 50 строк по умолчанию и максимум 200, даже если низкоуровневая read-модель допускает 500. Cursor включает выбранную стабильную сортировку и `id`. | принято в A0.1 |
| A-D102 | Revision аккаунта | В API `identity.revision` соответствует `IdentityRow.event_seq`; версия отдельного region/data передаётся дополнительно для точечной команды. Command gateway проверяет ожидаемую revision атомарно и возвращает `412` при конфликте. | принято в A0.1; библиотека D-122 |
| A-D103 | Read-контракты | Публичные read-модели админки принадлежат библиотеке Identity Hub и скрывают SQL/Store rows. Backend админки получает только типизированные безопасные DTO, даже если библиотека реализует запрос через SQLAlchemy Core. | принято в A0.1; библиотека D-122 |
| A-D104 | Разрешение пространства | Space-scoped endpoint сначала проверяет `AdminPrincipal.allowed_spaces`, затем вызывает публичный `IdentityHub.get_space()`. Неизвестный и недоступный slug дают одинаковый `404`; проверка никогда не создаёт пространство. | принято в A1.3; библиотека D-128 |
| A-D105 | Идемпотентность платформенного слоя | До появления долговечного admin mutation store в A4.1 общий adapter коалесцирует конкурентные повторы и кеширует успешный результат внутри процесса на один час. Standalone CLI запускает один worker. A4.8 заменяет/проверяет этот контракт для multi-instance deployment. | временно принято в A1.3 |
| A-D106 | Команды аренды, прокси и связей | Revoke использует доменный fencing; rebind резервирует capacity атомарно в библиотеке; unlink сначала получает транзитивный impact и при наличии зависимых аккаунтов требует acknowledgement `affects_dependents`. Checker прокси передаётся приложению как зависимость, а в demo используется детерминированный checker без сети. | принято в A3.4; библиотека D-129 |
| A-D107 | Повторная аутентификация и жизненный цикл раскрытого секрета | Reveal/update доступны только `admin` и требуют в теле запроса повторно предъявить текущий bearer-токен того же principal или настроенный admin-пароль. Secret payload не сохраняется в idempotency: запрос представлен SHA-256 fingerprint, результат reveal удаляется после завершения. Ответы имеют `no-store`; frontend держит значение только в локальном state и очищает его через 30 секунд, при blur, скрытии страницы, `pagehide` и `popstate`. | принято в A3.5; библиотека D-130 |
| A-D108 | Snapshot массовой операции | Preview хранит на сервере не фильтр для повторного вычисления, а ограниченный 1000 строками набор `(identity_id, revision)` на 15 минут. До появления долговечных admin-таблиц в A4.1 snapshot и прогресс попыток process-local; один `snapshot_id` сериализует execute, успешные строки повторно не выполняются, stale revision остаётся в частичном отчёте. Экспорт ограничен 1000 строками, строится из secret-free read-моделей, нейтрализует CSV formulas и аудируется только fingerprint фильтра и счётчиками. | временно принято в A3.6; библиотека D-131 |
| A-D109 | Управление доставками и одноразовые ключи | Кешируемая read-модель всегда маскирует Telegram target и путь/query webhook URL для всех ролей; полные target/token принимаются только write-only командами. Создание и ротация webhook генерируют ключ на сервере, возвращают его с `no-store` ровно одному получателю idempotency-результата и после этого оставляют только tombstone, поэтому повтор не выполняет команду и не раскрывает ключ. SSRF policy разрешает HTTPS и явно настроенные HTTP dev-hosts, запрещает credentials, local/private/service IP literals и локальные hostname suffixes; redirects не следуются, а production egress дополнительно ограничивается сетью deployment. Test-send обоих транспортов не пишет delivery и не двигает cursor; manual retry Telegram/webhook сбрасывает attempts, а webhook дополнительно включает endpoint согласно D-120. | принято в A3.8; библиотека D-132 |
| A-D110 | Возобновляемый импорт | API принимает содержимое UTF-8 CSV/JSONL как write-only поле с лимитами 10 МиБ, 10 000 записей и 5 секунд разбора. После строгой проверки библиотека присваивает строкам стабильные ID и хранит только envelope-encrypted staging. Dispatcher обрабатывает пакеты по 100 строк с claim token; истёкший claim можно забрать повторно, а уже созданный стабильный ID превращает повтор в успешный результат без дубля. Отмена применяется после текущего claimed-пакета. Терминальный переход удаляет staging, оставляя на 90 дней только счётчики и ограниченный redacted report. Viewer читает отчёты, operator/admin запускают и отменяют импорт. Audit содержит actor, reason, service, run ID и count, но не имя файла, строки или секреты. | принято в A3.7; библиотека D-134 |
| A-D111 | Tier-события и метрики | Переходы `identity.tier.reached/lost` вычисляются из effective verified factors и записываются в той же транзакции, что изменение verification region; повтор неизменившегося решения не создаёт событие. Встроенные метрики используют фиксированный набор label keys и ограниченные значения; identity, lease, event, run и external reference запрещены как labels. Ошибка пользовательского MetricsHook подавляется на стабильном синхронном adapter-е и не меняет результат доменной операции. Метрики acquisition/wait/empty, lease/operation duration/failure, pool availability, dispatcher cursor lag и delivery queue предназначены для оперативного мониторинга; долговечные административные ряды строит A4.3. | принято в A4.2; библиотека D-135 |
| A-D112 | Идемпотентные временные роллапы | `stats-rollups` читает внешние и внутренние events по `(tx_id, id)` и пересчитывает абсолютные значения только затронутых 1m/1h/1d корзин. Дневные границы следуют IANA-таймзоне пространства; read facade заполняет отсутствующие корзины нулями. MetricsHook пишет через process-local буфер вне critical path; flush получает UUID, а receipt и additive/set UPSERT выполняются одной транзакцией. Минутные данные хранятся 48 часов, rebuild расширяет диапазон до целых корзин и сверяется с raw events. | принято в A4.3; библиотека D-136 |
| A-D113 | Почасовые снимки состояния | На каждый UTC-час и пространство существует отдельный coverage marker, включая пустое пространство. Counts по service/region/state заменяются атомарно под блокировкой marker; уникальные ключи не дают двум workers создать дубли. Отсутствующая строка внутри complete frame означает ноль, отсутствие frame — ещё нет истории. Backfill снимает только текущий час и маркируется `source=backfill`; прошлая история из текущего состояния не синтезируется. Retention по умолчанию 365 дней. | принято в A4.4; библиотека D-137 |
| A-D114 | Аналитические read-модели | Backend получает только публичные secret-free DTO библиотеки. Каталог ограничивает диапазон 366 днями, 50 группами и 1000 точками; серверные buckets — 1m/1h/1d, а 5m/15m UI складывает из минут. Дневные границы следуют timezone пространства. Исторические ответы имеют детерминированный ETag и private revalidation. Coverage snapshot-данных complete только при наличии каждого часового marker. Utilization явно использует текущий eligible denominator, а lease operations относятся к часу начала аренды. Старые агрегатные import events без UUID входят в intake, но не связываются с индивидуальными funnel outcomes. | принято в A4.5; библиотека D-138 |
| A-D115 | Представление аналитики | Analytics — отдельный lazy route с воспроизводимыми URL-параметрами. Каталог API определяет допустимые dimensions; неподдерживаемый выбранный разрез сворачивается в общий ряд, а не отправляет заведомо ошибочный запрос. Независимые панели загружаются параллельно. Каждый график имеет постоянную табличную альтернативу и secret-free CSV/SVG export; вся страница экспортируется JSON. Formula, timezone, coverage и previous-period показываются рядом с данными. | принято в A4.6 |

## Как фиксировать отклонение

Добавьте строку `A-D1xx` с причиной, решением и затронутыми задачами. Если изменение влияет на
схему или публичный API библиотеки, одновременно добавьте новую запись `D-1xx` в
[`docs/plan/DECISIONS.md`](../plan/DECISIONS.md). После этого обновите спецификацию задачи в
`PLAN.md` и зависимости в `PROGRESS.md`, не удаляя историю старого решения.
