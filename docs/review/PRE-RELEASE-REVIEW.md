## 1. Исправить до публикации

### R1-01. Фикстура `identity_hub` из pytest-плагина не работает по умолчанию

- Где: `src/identity_hub/testing/pytest_plugin.py:56`, entry point `pytest11` в `pyproject.toml`.
- Подтверждение: **запуск** (wheel в чистом окружении, Python 3.13).
- Что не так: фикстура объявлена через `@pytest.fixture` как `async def`. В strict-режиме pytest-asyncio (режим по умолчанию) и без pytest-asyncio тест падает на setup: `requested an async fixture 'identity_hub', with no plugin or hook that handled it`. Работает только при `asyncio_mode = "auto"`.
- Последствие: плагин грузится автоматически у всех, кто установил пакет; первый же тест пользователя по руководству может упасть.
- Исправление: `pytest_asyncio.fixture` либо синхронная фикстура с ленивым `start()`; тест плагина в strict-режиме.
- План: новое.

### R1-02. Повтор операции с тем же `key` после неуспеха неотличим от повтора после успеха

- Где: `src/identity_hub/postgres/store.py:1077` (`charge_quotas`), `src/identity_hub/operation.py:108`, руководство `docs/guide/07-leases.md:87`, `docs/guide/12-recipes.md:106`.
- Подтверждение: **запуск** на `MemoryStore`; путь в `PgStore` прослежен чтением (`ON CONFLICT DO NOTHING` → `duplicate=True` без чтения `outcome`).
- Сценарий: первая попытка `lease.operation("send", key="job:1")` падает с сетевой ошибкой, ключ помечается `failed`. Ретрай с тем же ключом получает `op.duplicate=True`. Руководство учит писать `if not op.duplicate:` — тело пропускается, отправка не повторится никогда. Исход первой попытки из `Operation` узнать нельзя.
- Исправление: отдавать исход прошлой попытки (`op.previous_outcome`) либо разрешать повтор после `failed`; описать семантику в руководстве.
- План: I1.3 трогает `ih_operation_keys`, но семантику «повтор после failed» не описывает — нужно решение.

### R1-03. Один неудачный heartbeat теряет аренду

- Где: `src/identity_hub/lease.py:154` (`_heartbeat_loop`).
- Подтверждение: **чтение**.
- Сценарий при настройках по умолчанию (TTL 60 с, heartbeat 20 с, `safety_margin` 20 с): heartbeat на 20-й секунде падает из-за короткого сбоя БД. Следующий сон — `min(20, дедлайн − сейчас) = 20` с, вторая попытка приходится ровно на дедлайн (40 с) и получает бюджет `max(0.001, 0)` = 1 мс. Аренда объявляется потерянной, владеющая задача отменяется. Один сбой БД отменит все активные аренды воркера.
- Исправление: после неудачи повторять быстро (короткий backoff в пределах оставшегося бюджета), а не через полный интервал.
- План: новое (I2.2 про пакетный heartbeat это не покрывает).

### R1-04. SSRF через вебхуки по DNS

- Где: `src/identity_hub/dispatch/webhooks.py:146` (`validate_webhook_url`), `:346`, `:399`; `src/identity_hub/telegram_notify/__init__.py:85`.
- Подтверждение: **чтение**.
- Что не так: проверка отсекает только IP-литералы и суффиксы `localhost`/`.local`/`.internal`. Имя, которое резолвится в 10.x или 169.254.169.254, проходит; адрес фактического соединения не проверяется (DNS rebinding). `httpx.AsyncClient` создаётся без `trust_env=False` и подхватит `HTTP_PROXY`/`ALL_PROXY` из окружения.
- Смягчение: редиректы отключены, тело ответа не сохраняется (слепой SSRF с оракулом по коду и времени).
- Исправление: резолвить имя и проверять адрес на установленном соединении (pin IP через transport), `trust_env=False`, документировать вынос доставки в изолированную сеть.
- План: новое.

### R1-05. Медленный получатель вебхука блокирует весь диспетчер

- Где: `src/identity_hub/dispatch/webhooks.py:389` (`deliver_due`), `src/identity_hub/dispatch/dispatcher.py:86` (`run_once`).
- Подтверждение: **чтение**.
- Что не так: до 100 доставок отправляются последовательно с таймаутом 10 с каждая, захват доставки (`claim_for`) живёт 30 с. Худший случай — около 1000 с на пачку; всё это время стоят остальные потребители и pump-ы (импорт, maintenance, rollups, уведомления). Второй экземпляр диспетчера перехватит истёкшие захваты и доставит повторно.
- Исправление: параллельная доставка с ограничением на endpoint, захват с продлением или меньшая пачка, отдельный бюджет времени на pump.
- План: новое (I5.2 унифицирует воркеры, но проблему не называет).

### R1-06. «Ядовитое» событие навсегда останавливает подписчика

- Где: `src/identity_hub/dispatch/dispatcher.py:68` (`subscribe`), `:86` (`run_once`); `src/identity_hub/postgres/store.py:3636` (`process_events`).
- Подтверждение: **чтение**.
- Что не так: исключение в колбэке откатывает сдвиг курсора для всей пачки; пачка повторяется каждые 2 с без лимита попыток и без отложенной очереди. События пачки, обработанные до сбойного, приходят повторно на каждом круге.
- Исправление: сдвиг курсора по одному событию для колбэков, лимит попыток с уводом в dead-letter и событием об этом.
- План: новое.

## 3. Что сделано хорошо

- **Аренда:** время берётся из БД; эксклюзивность держится на `FOR UPDATE` плюс `ON CONFLICT … WHERE expires_at <= now()`; fencing монотонный; клиентский дедлайн считается по monotonic с запасом; сильная ссылка на heartbeat-задачу; отмена тела превращается в `LeaseLost` с `uncancel()`.
- **Outbox:** курсор `(tx_id, id)` с горизонтом `pg_snapshot_xmin` — потеря событий при коммите не по порядку закрыта; взаимное исключение экземпляров через `FOR UPDATE SKIP LOCKED` на курсоре.
- **Шифрование:** AES-256-GCM, DEK на запись, случайный nonce, AAD привязан к таблице, владельцу, слоту и версии схемы, `key_id` хранится рядом, legacy-формат читается.
- **Квоты:** атомарный upsert с условием `used < limit`, откат всех окон при исчерпании одного, окно считается по времени БД.
- **Подпись вебхуков:** HMAC-SHA256 по `timestamp.body`, `compare_digest`, окно повтора 5 минут, две подписи на время ротации, есть `verify_signature` для получателя.
- **Миграции:** своя таблица версий `ih_alembic_version` в схеме библиотеки, транзакционный advisory lock, `start()` миграции не применяет.
- **Упаковка:** wheel (110 файлов) и sdist собираются; оба примера проходят из чистой установки на Python 3.12 и 3.13 без extras; `import identity_hub` не тянет SQLAlchemy, Alembic, httpx и pytest; глобального состояния нет; окружение читают только CLI и `EnvSecretsProvider`; имя `identity-hub` на PyPI свободно.

#### Исправить до публикации

**R2-S01. Ключ идемпотентности аренды выдаёт чужой аккаунт вместе с credentials** (запуск, MemoryStore и PostgreSQL; план: I1.3).
- Где: `src/identity_hub/lease.py:500`, `src/identity_hub/postgres/store.py:784`, `:827`.
- Что не так: повтор `pool.lease(idempotency_key=…)` с тем же ключом из пула другого сервиса возвращает ту же аренду с тем же `token`. Чужой пул расшифровывает credentials аккаунта другого сервиса и своим `release()` снимает чужую аренду.
- Тот же ключ в другом пространстве на PostgreSQL даёт сырой `sqlalchemy.exc.IntegrityError`, текст которого содержит `[parameters: …]` с `token` новой аренды. `MemoryStore` в этом случае выдаёт свою аренду — расхождение бэкендов.
- Обнуление истёкших ключей (`store.py:827`) идёт без фильтра по `space_id`.
- Исправление: уникальность ключа в пределах пространства; сверка пула, сервиса и holder при повторе; I1.3 стоит выполнить до публикации.

**R2-S02. Токен бота Telegram попадает в лог приложения через httpx** (запуск; новое).
- Где: `src/identity_hub/telegram_notify/__init__.py:56`.
- Что не так: токен — часть URL, а httpx пишет каждый запрос на уровне INFO. При обычном `logging.basicConfig(level=INFO)`: `httpx INFO HTTP Request: POST https://api.telegram.org/bot123456:AAE-LEAK-BOT-TOKEN/sendMessage "HTTP/1.1 200 OK"`. У `TelegramUnavailable` в `__context__` остаётся исключение httpx с токеном.
- Исправление: фильтр на логгере `httpx`, вырезающий `/bot<…>/`; очищать `__context__`.

**R2-S03. `token` аренды попадает в логи библиотеки и в сообщения исключений** (запуск на PostgreSQL; IMP-13 заявлен выполненным, фактически открыто).
- Где: `src/identity_hub/lease.py:169`, `:414` (`exc_info=True`); `postgres/store.py` нигде не оборачивает `DBAPIError`.
- Что не так: текст ошибки SQLAlchemy содержит `[parameters: …]`; для `extend_lease`, `release_lease` и вставки аренды среди параметров есть `token`. **R2-F03. Telegram: массовое событие теряет уведомления, большой дайджест умирает целиком** (запуск; новое).

### Публичный API и первая публикация

1. **Резервируйте пространство имён.** Pydantic v2 переименовал все методы в `model_*` ([migration](https://pydantic.dev/docs/validation/latest/get-started/migration/)).
2. **Не меняйте семантику под тем же именем.** pyrate-limiter v4: `try_acquire` стал блокировать вместо исключения ([migrating](https://github.com/vutran1710/PyrateLimiter/blob/master/docs/migrating.md)).
3. **Значения по умолчанию — часть контракта.** pg-boss v10 перевернул ретраи с opt-in на opt-out. У нас TTL, heartbeat и таймауты стоит перечислить в одном месте документации.
4. **`DeprecationWarning` не работает.** urllib3 2.6.0 удалил давно устаревший API и сломал клиентов ([Seth Larson](https://sethmlarson.dev/deprecations-via-warnings-dont-work-for-python-libraries)). Довод за R1-09.
5. **SemVer не спасает.** Любое наблюдаемое поведение станет зависимостью ([hynek](https://hynek.me/articles/semver-will-not-save-you/)). Зафиксировать письменно, что входит в контракт: имена и payload событий, коды ошибок, read-схема, формат шифртекста.
6. **Минимальная явная публичная поверхность** ([typing spec](https://typing.python.org/en/latest/spec/distributing.html)). У нас `__all__` и `py.typed` есть; `pyright --verifytypes` не запускался.
7. **Конструктор без ввода-вывода** ([Seth Larson](https://sethmlarson.dev/designing-libraries-for-async-and-sync-io)). У нас так.
8. **Никаких глобальных синглтонов** ([Tortoise 1.0](https://tortoise.github.io/migration_guide.html)). У нас так.
9. **Ядро не читает окружение неявно.** У нас читают только CLI и `EnvSecretsProvider`; исключение — httpx `trust_env` (R1-04).
10. **Переименование настроек — только с инструментом и мостом** ([Celery 4.0](https://docs.celeryq.dev/en/stable/history/whatsnew-4.0.html)).
11. **Формат хранения — самый дорогой контракт.** pg-boss 10, APScheduler 4, procrastinate 3. Нужен письменный протокол апгрейда и CI-тест «схема N−1 → upgrade → код N».
12. **Pytest-плагин — отдельный публичный API** ([pytest plugins](https://docs.pytest.org/en/stable/how-to/writing_plugins.html), [pytest-asyncio changelog](https://pytest-asyncio.readthedocs.io/en/latest/reference/changelog.html)). См. R1-01.
13. **Сообщение об ошибке должно называть причину и действие** (хороший образец — [asyncpg FAQ](https://magicstack.github.io/asyncpg/current/faq.html)).

### Ближайшие аналоги

- **[twscrape AccountsPool](https://github.com/vladkens/twscrape)** — пул аккаунтов с лимитами по операции; SQLite, один процесс, без TTL и fencing. Не брать бесконечное ожидание и ручной `reset_locks`.
- **[Crawlee SessionPool](https://crawlee.dev/js/docs/guides/session-management)** — жизненный цикл сессии, привязка к прокси; in-process. Взять раздельные сигналы «временная ошибка» и «блок».
- **[procrastinate](https://procrastinate.readthedocs.io)** — ближайший по форме: async Python поверх PostgreSQL, миграции в пакете, in-memory коннектор. Взять соглашение pre/post-миграций.
- **[River](https://riverqueue.com/docs) и [Oban](https://oban.hexdocs.pm)** — аренда строк со спасением зависших, идемпотентные миграции. Взять честную документацию границ и `migrated_version`.
- **[Vault leases](https://developer.hashicorp.com/vault/docs/concepts/lease)** — семантика lease/renew/revoke; transit — образец версии ключа в шифртексте.
- **[amazon-dynamodb-lock-client](https://github.com/awslabs/amazon-dynamodb-lock-client) и ShedLock** — аренда с heartbeat поверх обычной БД; fencing у обоих нет.
- **Standard Webhooks и Stripe webhooks** — образец подписи, ретраев и рекомендаций по SSRF.
- **Hangfire и pgqueuer** — библиотеки со своей схемой: уровни совместимости, CLI `install/upgrade` с `--dry-run`.
