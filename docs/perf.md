# Производительность Identity Hub

## Методика

Нагрузочные сценарии запускаются отдельно от обычного CI:

```bash
uv run pytest -m load -s tests/load/test_performance.py
```

Seed не входит в измеряемый участок. Для 10k/100k аккаунтов используется binary COPY через
asyncpg. Latency измеряется `time.perf_counter()` после прогрева; percentile — nearest rank.
Lease-сценарий запускает 50 конкурентных воркеров и после измерения проверяет:

- у 50 живых аренд 50 разных аккаунтов;
- `lease.fencing == identity.fencing_seq`;
- после release в пуле SQLAlchemy нет занятых соединений;
- неожиданных ошибок и deadlock нет.

## Контрольный прогон 2026-09-27

Окружение:

- Windows 11 Pro, AMD Ryzen 7 3700X (8 ядер / 16 потоков);
- Python 3.14.3;
- PostgreSQL 16 Alpine в Docker Desktop 29.2.1;
- asyncpg через SQLAlchemy, pool 10 + max overflow 40;
- база в Docker на той же машине;
- исходная точка: commit `2694442` + изменения P10.3.

| Сценарий | Объём | Результат | Бюджет | Статус |
|---|---:|---:|---:|---|
| Acquire lease, 50 воркеров | 10 000 аккаунтов | p50 3382.10 мс; p95 3458.86 мс; p99 3561.33 мс; 13.93 op/s | p95 ≤ 20 мс | не достигнут |
| Operation `work` | 30 измерений | p50 4.44 мс; p95 5.69 мс; p99 6.10 мс; 220.21 op/s | p95 ≤ 10 мс | достигнут (`I6.1`, `D-329`: 11 → 3 запроса; до задачи p95 79.43 мс на той же машине) |
| Поиск по подстроке | 100 000 аккаунтов, 20 измерений | p50 79.08 мс; p95 121.18 мс; p99 125.89 мс; 12.00 op/s | p95 ≤ 100 мс | не достигнут |
| `import_many` | 10 000 аккаунтов, batch 2000 | 93.48 с | ≤ 60 с | не достигнут |
| Event commit → consumer | 20 событий | p50 35.16 мс; p95 47.43 мс; p99 50.26 мс | p95 ≤ 1 с | достигнут |

Результаты зависят от хоста и Docker Desktop, но превышения нельзя считать только шумом
окружения. Невыполненные бюджеты оформлены как обязательная
correction-задача PERF-1 в D-127; соответствующие load-тесты возвращают `xfail` с этой ссылкой.

## Найденная гонка

Первый прогон 50 acquire обнаружил безопасный, но ошибочный отказ: запрос кандидата видел снимок
до конкурентного commit аренды, после чего `acquire_lease` находил уже живую строку и возвращал
`LeaseUnavailable`. P10.3 добавил повтор выбора с исключением конфликтного кандидата (D-126).
После исправления все 50 выдач завершаются, аккаунты уникальны, fencing согласован.
