# Identity Hub — инструкции для агента

Python-библиотека управления парком аккаунтов. ТЗ: `identity-hub-requirements.md`.
Язык общения, комментариев и документации — русский; идентификаторы — английские.

## Протокол автономной работы

Базовый план v1 завершён. Активная очередь улучшений ведётся по
`docs/plan/IMPROVEMENTS-PLAN.md` с сохранением прогресса в
`docs/plan/IMPROVEMENTS-PROGRESS.md`. Источник требований очереди —
`docs/plan/IMPROVEMENTS.md`; исходный план и его история остаются в `PLAN.md` и `PROGRESS.md`.

Если в `IMPROVEMENTS-PROGRESS.md` есть `in_progress` или `todo`, использовать план улучшений,
прогресс улучшений и идентификаторы `I<фаза>.<номер>`. После полного завершения этой очереди
вернуться к `PLAN.md`/`PROGRESS.md` только при появлении в них новых незавершённых задач.

Каждая сессия (в том числе запуск через `/loop`) выполняет цикл для активного плана:

1. **Восстановить контекст.** Прочитать активный файл прогресса (раздел «Текущая задача» и таблицу),
   `docs/plan/DECISIONS.md`, затем раздел нужной задачи в активном плане. Для улучшений дополнительно
   прочитать соответствующие `IMP-NN` в `IMPROVEMENTS.md`. Выполнить `git status` и `git log --oneline -5`.
2. **Если есть задача `in_progress`** — продолжить её с первого неотмеченного шага в «Текущей задаче».
   Незакоммиченные изменения сверить с шагами: довести до конца или откатить только своё незавершённое.
3. **Иначе взять следующую:** первая `todo` в таблице, у которой все зависимости `done`.
   Записать её в «Текущую задачу» с разбивкой на 3–8 шагов, статус → `in_progress`, закоммитить
   (`plan: start <ID>`).
4. **Выполнить** по TDD: тесты из DoD задачи → реализация → рефакторинг. После каждого завершённого шага
   отметить `[x]` в «Текущей задаче» (это чекпоинт на случай обрыва сессии).
5. **Проверить** (обязательно, вывод прочитать):
   ```
   bash scripts/check.sh      # ruff --fix-only, format, ruff check, mypy src, lint-imports, pytest -m "not load"
   ```
6. **Закрыть:** статус → `done`, «Текущую задачу» очистить, обновить «Итого», добавить строку в «Журнал сессий»
   (коммиты задачи находятся через `git log --grep <ID>`; колонка «Коммит» — необязательна). Закоммитить код и прогресс **одним коммитом**:
   `feat(<ID>): <кратко>` (+ ссылки на IMP/FR/G в теле).
7. Перейти к шагу 3, пока хватает контекста. Перед остановкой — всегда оставить «Заметки для следующей сессии».

### Правила

- Не останавливаться на открытых вопросах ТЗ: применять решения из `DECISIONS.md`; если решения нет —
  выбрать разумный вариант, записать новую `D-NNN` со статусом `по умолчанию` и продолжать.
- **Blocked** — только при внешней причине (нет Docker, нет сети, противоречие ТЗ без безопасного выбора):
  статус `blocked`, причина в «Примечание», перейти к следующей доступной задаче.
- Не отмечать `done` без зелёной проверки из шага 5. Код возврата `scripts/check.sh` не терять в пайпе
  (`| tail` глотает ошибку): `bash scripts/check.sh > .check.log 2>&1; rc=$?; tail -3 .check.log; [ $rc -eq 0 ]`.
- Тесты со временем (аренда, heartbeat) гонять полным набором 2–3 раза перед закрытием задачи.
- Не отключать и не ослаблять тесты ради зелёного цвета.
- Задача оказалась слишком большой — разбить на `<ID>a/b` через запись в `DECISIONS.md` и таблицу активного прогресса.
- Схему БД менять только новой миграцией (D-012). Секреты и `token` аренды — никогда в логах/событиях.
- Коммиты — только в локальный git; `push` не делать без явной просьбы.
- До выполнения P0.1 репозитория нет: P0.1 начинается с `git init` и первого коммита плана и ТЗ.

### Утилита прогресса

- Базовый план: `python docs/plan/progress_tool.py start|check|note|done|status ...`.
- Улучшения: `python docs/plan/improvements_progress_tool.py start|check|note|done|status|show ...`.

Шаги 3, 4 и 6 делать утилитой активного плана, чтобы формат таблицы не ломался.

## Окружение

- Windows 11, Python 3.14 в `.venv`, менеджер — `uv`. Docker доступен (testcontainers, PostgreSQL 16).
- Тесты с БД: маркер `pg`; можно указать `IH_TEST_DATABASE_URL` вместо testcontainers.
- Локальная БД для отладки: `docker compose up -d` (после P0.3).
